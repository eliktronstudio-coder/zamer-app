# ADR 0007: аккаунты и транзакционная синхронизация

Статус: реализовано для подключения; внешний проект Supabase отложен по решению пользователя.

## Решение

Supabase Auth отвечает за email/password, регистрацию, восстановление и обновление пароля. SDK находится в адаптере; геометрия и локальные репозитории от него не зависят. Без URL/публичного ключа приложение полностью работает гостем. Гостевые объекты отправляются только после явного «Сохранить объект в облаке». Вход сам по себе не присваивает их аккаунту.

IndexedDB обновлена до Dexie v5: добавлены cloudStates, outbox, cloudConflicts. Формат геометрии/project.json остаётся v4. Локальная правка, revision и маркер outbox записываются одной транзакцией. Worker атомарно собирает согласованный snapshot всего объекта, фиксирует UUID команды и payload. Уже отправленный payload неизменяем: новые правки получают отдельные маркеры. Повтор отправляет тот же UUID/payload. Серверный ACK удаляет только соответствующую команду; локальные данные и более новые правки остаются. Retry сохраняется в IndexedDB, с exponential backoff 2–300 секунд; online и таймер возобновляют отправку, кнопка позволяет повторить немедленно.

RPC zamer_push проверяет auth.uid(), owner, identity и base revision под транзакционными advisory locks. Команда хранит SHA-256 отпечаток запроса и неизменяемый ответ: повтор возвращает прежний ACK, другое содержимое с тем же UUID отклоняется. Объект, этажи и отдельные типизированные строки сущностей обновляются атомарно, snapshot каждой принятой версии сохраняется отдельно. Правки через прямой REST write запрещены. zamer_list возвращает текущие версии только владельца через RLS.

0001_initial.sql сохраняется как ранняя модель сущностей. Рабочий transport использует отдельные cloud_projects/cloud_floors/cloud_entities из 0002, с JSON-полями конкретной сущности, а не один JSON объекта как единственный источник. cloud_versions — резервные снимки. Старые таблицы не используются новым worker; будущие запросы должны обращаться к cloud_*.

## Конфликты и аккаунты

Устаревшая база получает conflict с текущей серверной версией. Обе версии записываются локально, отправка объекта приостанавливается. Даже более новая версия при явной загрузке уже существующего объекта требует выбора: редактор не перезаписывается в фоне. Пользователь может открыть отдельную локальную копию либо принять облачную с обязательным сохранением своей копии. Новые UUID переназначаются вместе со ссылками комнат, проёмов, размеров и junctions. Не восстановленные recovery drafts блокируют принятие облачной версии. Merge отдельных стен пока не реализован.

Перед сменой аккаунта редакторы проходят flush. Worker прежнего аккаунта останавливается; поздний ответ не удаляет его очередь. Локальные owned-проекты доступны только текущему owner, guest-проекты доступны всем локальным сессиям. Выход не удаляет данные. Это разделение интерфейса и репозитория, а не шифрование IndexedDB: владелец браузера/devtools имеет доступ к физическим данным.

## Файлы и пределы

0003 создаёт private bucket zamer-originals, чтение/добавление только владельцем объекта по пути projectUUID/filename. Обновление и удаление оригиналов запрещены политиками. Загрузка фото, checksum, signed URLs и lifecycle появятся в фазе 8.

SQL проверяет identity, версии, коллекции, уникальные UUID, размеры, координаты и основные ссылки; строгий клиентский parseSnapshot дополнительно проверяет полную модель. SQL ещё не дублирует весь геометрический движок и рекурсивную валидацию сечений колонн. Перед публичным запуском нужны полная проверка входа backend, ограничения размера запросов/квоты, пагинация, retention версий/команд, мониторинг и испытания настоящего Supabase. Снимки версий не заменяют независимый backup базы и Storage. Автоматическая 30-дневная очистка корзины не включена.

## Доказательства

Тесты IndexedDB проверяют rollback outbox, неизменяемую отправку, поздние/повторные ACK, retry, смену аккаунта, миграцию v4→v5, конфликт и сохранение связей копии. PGlite исполняет все три SQL-миграции, CAS RPC, idempotency, RLS двух пользователей, запрет анонимных/прямых записей и Storage policies. Browser тестирует SDK против имитированных Auth/RPC endpoints на desktop/mobile. Реальные Auth email redirects, PostgREST и Storage сервисы пока не проверены: пользователь настроит Supabase позже.
