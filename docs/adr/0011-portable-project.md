# ADR 0011: переносимый ZIP и атомарный импорт

Принято в фазе 11. Полный экспорт должен сохранять редактируемую модель и исходные файлы, а импорт — создавать отдельную копию без перезаписи существующего объекта.

ZIP содержит `00_Общий_отчет/report.pdf` и историю, `01_Планы/*.jpg`, `02_3D/*.jpg`, `03_Дефектная_ведомость/defects.pdf`, `04_Смета/estimate.pdf`, `05_Фотографии/<этаж>/<помещение>/<оригинал>` и `06_Исходные_данные/project.json`. Пустой раздел фото/недоступный WebGL имеет README; недоступный 3D явно отмечен. Имена нормализуются NFC, небезопасные символы заменяются, UUID исключают совпадения пользовательских названий. PDF и изображения создаются из зафиксированной модели после flush; история сохраняется готовыми файлами без перезаписи.

Envelope `format=zamer-project`, `packageVersion=1` содержит snapshot v5, цены используемых работ, состав сметы, original manifests, историю с immutable источниками, artifacts и предупреждения. Цены других объектов не включаются. SHA-256, размер и MIME связывают метаданные с байтами. Это проверка целостности, без подписи авторства. Оригиналы нужны также для корзины и исторических источников; при отсутствии экспорт завершается понятной ошибкой вместо неполной резервной копии.

Используется fflate; экспорт хранит уже сжатые JPEG/PNG/PDF без повторного сжатия. Импорт принимает store/deflate, проверяет central/local headers, CRC, безопасные пути, регистр имён, реальные размеры распаковки и SHA-256. Запрещены traversal, абсолютные пути, Windows reserved names, симлинки, шифрование, multidisk и ZIP64. Неперечисленные файлы отвергаются. Лимиты: ZIP 256 МБ, распакованные данные 512 МБ, файл 52 МБ, project.json 20 МБ, 10000 записей; модель до 5000 стен/5000 конструкций/2000 помещений. Проверка в Worker ограничена 30 секундами. Эти пределы ограничивают обработку, но не доказывают производительность на максимальных объёмах.

После проверки пользователь видит состав и задаёт имя. Импорт переназначает UUID рабочей модели и ссылки, создаёт гостевой объект в одной транзакции Dexie v8 вместе с файлами, историей и исключениями. Сбой квоты/смена аккаунта отменяет запись. Старые отчёты сохраняют исходные UUID внутри immutable источников и строк, а сами документы получают новую локальную identity. Cloud state/outbox/ACK и чужие ownerId не импортируются. Облачное сохранение остаётся явным действием пользователя.

`projectWorkPrices` добавляет цены копии отдельно от глобального справочника и по текущему аккаунту. При правке цены соответствующее переопределение снимается. Реальная миграция v7→v8 сохраняет прежние документы/цены. Snapshot v5, geometry v4, SQL 0001–0004 и cloud RPC v5 остаются прежними.

Отдельный project.json поддерживается для переносимого envelope и прежних snapshots v1–v5. Без ZIP модель/цены/состав доступны, но оригиналы/история не восстанавливаются; предупреждение показывается до записи. Полная резервная копия требует ZIP. XLSX остаётся расширением табличного адаптера из ADR 0010. Реальные устройства, 2000 фото, нагрузка и live Supabase проверяются в фазе 12.
