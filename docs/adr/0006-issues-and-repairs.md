# ADR 0006: нестыковки и предложения исправлений

Принято в фазе 6. Геометрия, ручной ввод и расчёты остаются источниками истины; нестыковки — производные данные.

## Rule engine

`src/issues/engine.ts` предоставляет `IssueRule`, `RuleContext` и `evaluateIssues`. Правило возвращает записи с постоянным ключом, типом, серьёзностью, floorId, roomIds, elementIds, описанием и точкой показа. UUID исходных сущностей входят в ключ; случайные новые identity при пересчёте не создаются. Правила не меняют сцену. Ошибка расширения изолируется и показывает неполноту списка вместо падения редактора.

Проверяются модель/ссылки/измерительные конфликты, отсутствующий ручной размер стены, открытые концы и небольшие разрывы, наложения/дубли стен, пересечения внутри двух стен, размеры/положение/перекрытие проёмов, пересечение конструкций одного типа, помещения и неполный расчёт. Перепад лестницы/пандуса сравнивается только с двухточечной линией уровня, оба конца которой совпадают с концами конструкции в пределах 5 см. Отсутствие такой линии не выдаётся за проверенное соответствие. Различие перепада больше 1 мм отмечается; размеры не переписываются. Балки на непересекающихся высотных интервалах не считаются накладывающимися.

Список в store обновляется после каждой команды, undo и redo. Панель читает сохранённые этажи объекта одной транзакцией Dexie liveQuery, заменяя текущий этаж живой сценой. Фильтры: весь объект/текущий этаж/серьёзность. Если чтение остальных этажей не удалось, текущие проверки доступны, неполнота обозначена. До окончания первого чтения отображается ожидание. Нестыковки не записываются в IndexedDB/snapshot: при offline reload выводятся заново из сохранённой сцены. Модель остаётся v4, миграция для фазы 6 не нужна.

Ошибки сохранения и конфликты вкладок добавляются из фактического состояния SaveQueue, не имитируют будущий серверный sync. Основной план и recovery copy не объединяются автоматически. Сохранённые recovery drafts доступны прежним механизмом восстановления.

## Показать

Текущий этаж: выбирается доступный проблемный элемент, переключается «Выбор» и создаётся запрос camera focus. Canvas подбирает масштаб/центр по его геометрии и прокручивает план в видимую область. Данные и история не меняются. При потерянной ссылке фокус использует исходную точку/начало этажа; рекурсивного перехода между неверными dimension references нет.

Другой этаж: React Router Link переносит issue target. Существующий перехват навигации ждёт flush SaveQueue; восстановленный редактор выделяет элемент и центрирует камеру. Программный переход не обходит защиту несохранённых изменений. Имена этажей/комнат и читаемые номера элементов видны в списке; внутренние rule IDs используются только как ключи и test hooks.

## Предложения

Ничего не исправляется при обнаружении. Панель открывает объяснение и явный выбор «Да, применить» / «Нет, оставить». Отказ скрывает предложение для этой версии сцены до закрытия редактора; это не удаляет нестыковку и не меняет проект. Отказы не являются долговечными согласиями/запретами.

1. Малый разрыв между свободными концами, больше геометрического epsilon и не более 5 см. Предлагается перенести целиком одну стену, сохранив её manual length, затем явно связать концы. Перед предложением проверяется constraint-команда, отсутствие новой коллизии стен и отсутствие прежней junction-привязки этих концов. Перенос связанных элементов обрабатывает существующий command layer. Это не растяжение стены и не изменение ручного размера.
2. Полностью совпадающие стены. Удаление предлагается только для дубля с такими же высотой/толщиной/ручной длиной/metadata и без связанных проёмов, размеров, junctions и сохранённых помещений. При неопределённости остаётся предупреждение для ручного решения.

Предложение содержит fingerprint всей сцены. При изменении плана открытое подтверждение перестаёт соответствовать предложению, а применение устаревшей команды отклоняется. Повторно проверяются constraint-результат, отсутствие новых пересечений и отсутствие новых ошибок связей/размеров. Исправление проходит через store commit, reconciliation комнат, пересчёт и прежнюю очередь сохранения. Это одна undoable команда. Расширять Repair нужно вместе с отдельными проверками безопасности и тестами; нельзя считать все предупреждения автоматически исправимыми.

## Завершение и границы

Ошибка/предупреждение, относящееся к комнате, учитывается проверкой её завершения. Можно продолжить исправление или завершить с замечаниями; редактор не блокируется. Информационные свободные концы отдельно стоящих стен не запрещают работу. Влияющие изменения завершённой комнаты по-прежнему возвращают её в работу.

Нет правил для ещё не реализованных дефектов/фото (фаза 8), работ/цен (фаза 10) и серверного sync (фаза 7). Фаза 6 показывает реальные локальные конфликты вкладок. Нет автоматического изменения существенной геометрии, автоподбора неизвестного wallId или применения типовых размеров. Наложение конструкций — предупреждение для проверки, а не утверждение о строительной ошибке; допустимость/нагрузки/нормативы не вычисляются. Сравнение уровней по площади, многоэтажные лестницы и сложные конструкции потребуют явно заданных связей. Попарные проверки O(n²) и все этажи объекта пока не проверены на нагрузке фазы 12. Реальные устройства/Safari не заменяются Chromium mobile emulation.
