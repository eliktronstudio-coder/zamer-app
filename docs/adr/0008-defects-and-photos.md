# ADR 0008: дефекты, фотографии и оригиналы

Статус: реализовано; внешний Supabase по прежнему выбору пользователя подключается позже.

## Данные и привязки

Dexie v6 добавляет defects, photos, photoFiles и photoTransfers без изменения прежних данных или неизменяемых команд outbox. project.json/snapshot — v5, geometrySchemaVersion — v4. Snapshot v1–v4 мигрирует в памяти с пустыми дефектами/фото. Metadata содержит UUID, project/floor/room/element bindings; фото дополнительно ссылается на дефект. Проверяются owner scope, новые ссылки, версии и идентичность пути оригинала. Изменение привязок дефекта атомарно обновляет его фотографии.

Дефект хранит тип (с редактируемыми предложениями), описание, точку/область, поверхность, длину/ширину/глубину, комментарий, рекомендуемый вид работ и open/resolved статус. Площадь и объём вычисляются только при необходимых размерах; это произведения введённых размеров, а не вывод о реальной форме дефекта. Repository.report даёт данные для будущих документов без повторного ввода. Каталог типов можно расширить; административный справочник не реализован.

Редактор «Дефект» отмечает точку на плане без изменения геометрии. По кнопке «Показать» viewport центрируется. Область задаётся списком точек. Маркеры видны независимо от выбора инструмента. Формы требуют явного сохранения; история Undo/Redo геометрии не управляет дефектами/фотографиями. Defect revision защищает от перезаписи второй вкладкой. Удаление геометрического элемента сохраняет историческую привязку и предупреждение; документ/фото не уничтожаются. Новое назначение требует существующего элемента.

## Оригиналы и память

JPEG/PNG/WebP/HEIC/HEIF, 1 байт–50 МБ, до 2000 записей фото на объект, включая корзину. Проверяются MIME и сигнатура; SVG/прочие файлы отвергаются. Файлы обрабатываются последовательно. Оригинальные байты и lastModified сохраняются отдельно от имени/подписи/привязок. SHA-256 одновременно проверяет целостность и дедуплицирует бинарные данные на устройстве. Превью JPEG quality 0.8 имеет сторону не больше 1280 px; браузер декодирует ориентацию. EXIF исходника не удаляется. HEIC/повреждённое изображение может не иметь превью в данном браузере; оригинал доступен для скачивания. URL Blob освобождаются при обновлении/закрытии карточки.

Оригинал, превью, metadata, project revision и outbox marker записываются одной транзакцией. Hash/decode выполняются заранее, чтобы IndexedDB-транзакция не завершилась во время внешнего async. Отказ quota откатывает всё. Нет гарантии сохранности после очистки браузера; приложение это не выдаёт за cloud backup.

## Cloud и lifecycle

0004 добавляет отдельные cloud_defects/cloud_photos с owner RLS и расширяет CAS RPC для v5, сохраняя совместимость неизменяемых v4-команд. Бинарные данные не попадают в JSON/PostgreSQL. Storage путь: projectUUID/photoUUID/checksum. Bucket private, upsert запрещён. После принятия metadata transport отправляет оригиналы, скачивает их обратно через авторизованный SDK и сверяет размер/SHA-256. Только затем local outbox принимает ACK. Receipt привязан к checksum/path. Потерянный ответ повторяется тем же command UUID; если оригинал уже существует, он проверяется, а не перезаписывается. Upload failure оставляет локальные данные/очередь и отдельную ошибку файлов.

Новое устройство загружает metadata, затем явно загружает выбранные оригиналы в локальный кеш с проверкой checksum. Весь объект с 2000 фото не скачивается автоматически. Пока первоначальная отправка файлов не завершена, другой клиент может получить metadata и увидеть недоступный оригинал; retry исходного устройства завершает отправку. PostgreSQL и Storage не имеют общей транзакции. Live Auth/Storage не проверены без проекта пользователя.

Фото/дефект удаляются обратимо через deletedAt. Архив/корзина объекта сохраняют связанные записи и файлы. Физического удаления/сборщика неиспользуемых оригиналов нет: текущая политика сохраняет исходники, включая версии и корзину. Cloud version snapshots сохраняют metadata; независимый backup Storage остаётся инфраструктурной задачей.

Conflict copy переназначает defect/photo IDs и все bindings/path, а локальный бинарный оригинал используется по тому же checksum. При отсутствии локального оригинала принятие конфликта блокируется до его загрузки, чтобы гостевая копия не потеряла доступ к файлу. Старые версии/оригиналы сохраняются. Floor recovery относится к геометрической сцене; дефекты/фото остаются привязаны к исходному этажу, а не дублируются автоматически.

## Ограничения перед Beta

Реальные мобильные камера/HEIC/очень большие файлы, 2000 фото, quota/persistent storage и независимые backups требуют проверки на устройствах. Хранение всего файла и SHA-256 создаёт временную нагрузку памяти; потоковая загрузка/ресайз decoder пока не реализованы. Нет редактора аннотаций поверх фото или выбора области мышью: область задаётся координатами. Формирование PDF/ведомости — фаза 10; полный экспорт файлов — фаза 11. До публичного запуска остаются backend hardening/квоты/retention/мониторинг из ADR 0007.
