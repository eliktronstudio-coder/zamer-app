## Зависимости

React + TypeScript + Vite; react-router-dom для URL проекта/этажа; Dexie для нормализованных локальных таблиц; Zod для границ; Zustand зарезервирован для editor state. Vitest + fake-indexeddb для моделей/транзакций; Playwright для пользовательских сценариев; ESLint и tsc; vite-plugin-pwa/Workbox для shell offline. Konva/react-konva и Three.js подключаются только в фазах 3 и 9, Supabase SDK — в фазе 7. Сейчас эти пакеты не нужны и не имитируются.

## Источник истины

UUID — идентификаторы всех сущностей. GeometryElement — discriminated union. Все координаты/длины/высоты в метрах, радианы для rotation, local XY; высота/уровни по Z. Денежные цены — целые копейки. Пользовательский измеренный размер — measuredLength без округления, независимо от точности отображения. В фазе 2 управляющий constraint устанавливает endpoint из направления и исходного measuredLength. Для связей стен нужен общий граф junctions; точки с близкими координатами автоматически не объединяются. Предложения изменения графа проходят явные команды пользователя.

UI не вычисляет бизнес-итоги и не записывает отдельную 3D-геометрию. Результаты расчётов и 3D — проекции модели с sourceRevision. Расчётный DAG: walls/openings → поверхности; boundary/holes → площади; поверхности/дефекты → объёмы работ → цены/смета → документы. Инвалидация по ID и revision, неподтверждённые значения помечаются incomplete.

## Границы фаз

Фаза 0: документы, модели, версия экспорта, SQL, тестовая инфраструктура. Фаза 1: локальные гостевые проекты/этажи, пустой лист, PWA. Drawing/undo и рабочий geometry engine требуют фаз 2–3. Auth/cloud не изображаются работающими. Все отсутствующие функции явно описаны как TODO, фиктивных кнопок нет.

## Альтернативы

Один JSON blob проще, но мешает индексации и sync — используется только для interchange/backup. Логика в React ускорила бы первый прототип, но создала бы независимые расчёты для 2D/3D — отвергнута. Real-time collaboration, AI и BIM отложены согласно ТЗ.
