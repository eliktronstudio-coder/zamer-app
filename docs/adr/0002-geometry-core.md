# ADR 0002: геометрическое ядро и явные связи концов стен

Статус: принято и реализовано для Фазы 2. Дата: 08.10.2026.

## Координаты и численная точность

Ядро не импортирует React, Dexie, Zustand, Konva или SDK backend. Координаты и длины — метры; rotation — радианы. Все функции возвращают новые значения и не изменяют входы. Представление number хранит исходный manual input без display rounding. `parseLengthInput` принимает десятичную точку/запятую и необязательный суффикс м/m, отвергает пустые, отрицательные, нулевые, нечисловые и неоднозначные записи.

Численный геометрический допуск — `GEOMETRY_EPSILON = 1e-9 м`. Это расстояние, а не площадь детерминанта и не экранный радиус. Проверка measuredLength дополнительно учитывает машинную точность абсолютных координат (8 ULP относительно масштаба). Малые изменения пользователя не отбрасываются даже внутри допуска. Для замеров предпочтителен локальный origin, чтобы избежать квантования на очень больших координатах. Неограниченные числа/переполнение отклоняются с явной ошибкой; геометрия не заменяется NaN/Infinity.

`robust-predicates` (зафиксирован lockfile) добавлен для адаптивного orient2d: почти параллельные направления не классифицируются как параллельные только по величине произвольного epsilon. Результат пересечения — none, point или overlap с двумя концами интервала. Нулевые сегменты обрабатываются отдельно. Проекция на ось бесконечна, ближайшая точка ограничена отрезком. Tolerance допускает близость параллельных линий и концов, но не объединяет их в модели.

Площадь простого контура вычисляется относительно первой вершины с компенсированным суммированием; это сохраняет малые площади далеко от нуля. Автоматическое обнаружение помещений, отверстия и проверка самопересечения контуров — Фаза 5. `polygonArea` пока не доказывает корректность топологии введённого контура.

## Стены и построение

Стена остаётся существующей сущностью Wall. `constructWall` применяет направление/ортогональность и подходящие привязки, затем управляющую длину. Manual length имеет приоритет. Если конечная точка после ввода длины не совпала с кандидатом snap, маркер возвращается null. Ядро не показывает фиктивное совпадение. Нулевая стена не создаётся. Перемещение/поворот сохраняют UUID, measuredLength и metadata. Физические края вычисляются из оси и thickness, без второй редактируемой геометрии.

`Transform2D` поддерживает композицию, инверсию, перемещение и поворот; матрицы пригодны для будущего screen/world viewport. Поворот стены использует арифметику относительно pivot. Масштабирование измеренных стен автоматически не предлагается.

## Привязки

Провайдеры: start, end, center, nearest, intersection, edge, far-edge, axis, linked. Каждый возвращает point, source elementIds и при необходимости guide. UI Фазы 3 отобразит эти данные; в Фазе 2 canvas отсутствует.

Радиус: tolerancePixels / pixelsPerMeter. Приоритет сначала семантический (концы/связи → пересечения → центр → края → ближайшая точка → ось), затем расстояние, затем стабильный ключ. Порядок входных стен не меняет выбор. По умолчанию start/end/center/intersection/nearest/linked включены; edges/axis доступны через enabledKinds. Другой тип добавляется провайдером без изменения алгоритма выбора. Выбор только на активном floorId. В orthogonal режиме snap допускается лишь на выбранном по указателю горизонтальном или вертикальном направлении.

Пересечения ищутся только среди сегментов в радиусе курсора. В плотном узле всё ещё O(k²); для редактора нужен viewport culling и позднее spatial index. Производительность 5000 элементов и реальные планшеты пока не проверены и не заявляются.

## Связи и ограничения

GeometryScene содержит Wall[], Junction[], Dimension[]. Junction хранит UUID, floorId и ссылки endpointReference на start/end; собственных координат у junction нет. Координаты принадлежат стенам, связь — явное ограничение совпадения. Само совпадение координат не создаёт связи. `connectEndpoints` соединяет только уже совпадающие концы, `detachEndpoint` явно разрывает связь. Закрытие небольших разрывов по предложению Да/Нет — Фаза 6.

Ассоциативный Dimension ссылается на стены через start/end/center. `evaluateDimension` вычисляет точки и значение по актуальным стенам; потерянные ссылки и другой этаж возвращают типизированную ошибку. Справочный размер не управляет стеной. В этой фазе управляющий размер связывает противоположные концы одной стены, `from` остаётся фиксированной точкой. Размеры между разными стенами можно читать, но управлять ими ещё нельзя.

Команды изменения размера, перемещения и поворота сначала создают новую модель в памяти, распространяют координаты по явным junctions и проверяют ограничения. Если возникает новый конфликт либо затронутый измеренный элемент противоречит manual length, команда возвращает ok:false без частичной модели. Введённые значения соседей не изменяются молча. Повторный управляющий размер той же стены также не переписывается автоматически.

Существующие несвязанные проблемы (например, размер на удалённую стену) не блокируют безопасные команды: успех содержит оставшиеся problems. Неоднозначные IDs/двойные endpoint membership или повреждённая форма данных требуют восстановления перед командой. Это ограничения корректности API, а не запрет пользователю работать с другим проектом.

Это локальный детерминированный решатель совпадений/длин, не общий нелинейный CAD solver: противоречащая цепочка отклоняется вместо выбора произвольного решения. changedWallIds/changedDimensionIds позволяют editor history, save queue и последующим расчётам инвалидировать связанные результаты.

## Сохранение и следующие фазы

Контракты PointReference/EndpointReference/Junction/Dimension валидируются Zod. Формат project.json v1 и Dexie v1 не меняются: UI ещё не создаёт геометрию, поэтому новые связи не записываются и не теряются при экспортировании. Нельзя считать snapshot v1 полным сохранением GeometryScene. Перед подключением редактора в Фазе 3 нужны versioned snapshot и Dexie migration для junctions/dimensions, тест восстановления и команды Undo/Redo. Запланированный SQL backend также потребует junction membership и constraints при Фазе 7.

Фаза 2 не включает canvas, touch-жесты, комнаты, opening constraints или панель «Нестыковки». Они подключатся к этому API в последующих фазах. Порядок разработки сохранён.
