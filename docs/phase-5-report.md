# Фаза 5: помещения и автоматические расчёты

Реализовано распознавание замкнутых контуров из стен, включая вогнутые комнаты, T-разделы/общие стены и вложенные границы с отверстиями. Площадь подписывается на плане сразу после замыкания четырёх стен. Пользователь добавляет помещение и задаёт собственное название; автоматических «кухонь» нет.

Редактор показывает пол/потолок, площадь контура, периметр, объём комнаты, поверхности каждой стены, окна/двери/прочие проёмы, чистые стены и длину/площадь откосов. Колонны вычитаются из пола/потолка без двойного учёта пересечений. Рассчитываются площади/объёмы колонн, балок, лестниц и пандусов, объём стен без проёмов и количества элементов. Итоги этажа обновляются после команды, итоги объекта — после локального ACK сохранения.

Статус работы отделён от замкнутости. Можно завершить с замечаниями, затем исправить помещение. Существенное изменение геометрии/проёма возвращает завершённую комнату в работу. Удаление стены сохраняет имя и identity комнаты, но не показывает ложную площадь; undo восстанавливает весь расчёт. Новый состав границы привязывается явно. Удаление помещения не удаляет стены.

## Изменённые компоненты

- `src/geometry/rooms.ts`, `src/calculation/{engine,quantities,project}.ts`: граф граней, зависимости, количества и итоги.
- `src/domain/{model,snapshot}.ts`, `src/infrastructure/{database,scene-storage}.ts`: модель v4, rooms, миграции, проверки контуров и recovery references.
- `src/editor/{store,commands,Canvas,Editor,Properties,RoomLayer,RoomProperties,CalculationPanel,ConstructionProperties}.tsx/ts`: выбор комнат, статусы, свойства, маркировка и глубина откосов; `src/app/styles.css`: адаптивные панели.
- `src/features/projects/{Workspace,ProjectQuantities}.tsx`: итоги сохранённых этажей объекта.
- `package.json`, `package-lock.json`: `polygon-clipping` для объединения и вычета следов конструкций.
- Геометрические, store, storage и браузерные тесты; README, карта требований, стратегия проверок и ADR 0005.

## Проверки

`npm run check` (TypeScript, ESLint, Vitest, production/PWA build) и `npm run format:check`. Браузерные проверки выполняются с системным Chromium, desktop и mobile touch viewport. Новые сценарии: точный прямоугольник 4,257 × 3 м → 12,771 м²; независимый статус; завершение без имени с замечаниями; вычет окна; undo удаления стены/помещения; offline reload; итог объекта после сохранения. Реальные миграции IndexedDB и recovery проверяют сохранение точных чисел и ссылок. Результат: **205 unit/storage тестов** (12 файлов), **32 браузерных сценария** (16 × desktop/mobile) прошли. После заключительных изменений хранения и загрузки итогов повторены все 8 новых браузерных проверок помещений — успешно. TypeScript, ESLint, build/PWA и Prettier проходят.

## Известные границы

Методика — контур замера, без смещения на толщину стены. Объём комнаты не исключает конструкции; суммарные объёмы отдельных конструкций не исключают взаимные пересечения. Лестница — тело без плиты, пандус — клин без основания. Кривые следы колонн аппроксимируются; круг/эллипс для объёма аналитические. Неполные данные помечены; неизвестные количества не подменяются нулём. См. [ADR 0005](adr/0005-rooms-and-quantities.md).

Проверка завершения ещё не включает фотографии/дефекты (фаза 8). Постоянная панель нестыковок и предложения ремонта — следующая фаза 6. Работы, материалы, цены и ведомости — фаза 10. Cloud sync, 3D, импорт/экспорт и нагрузка 5000 элементов ещё не реализованы. Мобильная эмуляция Chromium не заменяет реальные iOS/Safari/Android.

Визуальный smoke-check 1366×900 и 390×844: нет ошибок JavaScript и горизонтального переполнения. Скриншоты сохранены в `/tmp/zamer-phase5/desktop.png` и `/tmp/zamer-phase5/mobile.png`. Объём конструкций включает стены без проёмов и отдельные строительные тела; каждый элемент учитывается один раз на этаже.
