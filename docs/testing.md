# Проверки и фазы

Каждая фаза: npm run typecheck; npm run lint; npm test; npm run build. Браузерные сценарии: npm run test:e2e после build. CI повторяет эти команды. npm ci использует lockfile; кэш в доступном каталоге.

Фаза 0–1: валидация пустых названий; UUID и ссылки; snapshot roundtrip/неизвестная версия; сохранение/повторное открытие; rollback транзакции; archive/trash/restore; конкурентные этажи. Браузер: guest → объект/этаж → пустой план → второй этаж → reload offline → archive/restore, desktop + touch viewport.

Geometry фазы 2–5: аналитические эталоны расстояний, пересечений, касаний, коллинеарности, свободных углов, привязок, неортогональных и вогнутых контуров, дыр, разрывов, больших координат; winding invariance; точное сохранение manual input. Golden tests driving dimensions → wall graph → room surfaces → opening subtraction → work quantities. Изменения управляющих размеров не должны ломать ссылки. Геометрический epsilon — отдельный от display rounding.

Sync фаза 7: offline edits/reload, outbox rollback, duplicated ACK, interruption during upload, stale revision, сохранение обеих конфликтных версий, retry/backoff, account switch/RLS isolation. Миграции: реальные fixtures предыдущих версий в отдельной DB + restore; не тестировать миграции, которых ещё нет.

Фазы 8–11: исходные фото не исчезают при PDF/export; MIME/размер; 2D→3D identity; quantity derivation, цены в копейках; JPEG/PDF fonts, ZIP path safety, import/export recovery.

Фаза 12: реальные Chrome/Safari/Edge/Opera, iOS/Android, планшет среднего класса, 1366×768, stylus/pinch, 5000 geometry elements/200 rooms/2000 photos, CPU/memory/culling. Chromium mobile emulation не считается реальным устройством или проверкой Safari. WebKit Playwright также не заменяет реальный Safari. HTTPS, Auth, rate limiting, RLS, restore, export и отсутствие data loss — обязательные критерии публичного запуска, пока не выполнены.

В текущей cloud-среде браузер запускается через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`. Системный Chromium 151: Playwright setOffline блокирует запросы, но после service-worker navigation navigator.onLine может снова стать true. Поэтому проверяются offline-индикатор перед reload, реальные неуспешные network requests после reload и сохранение нового этажа без сети. Это ограничение эмуляции не считается проверкой реального offline-индикатора Safari/iOS.

Фаза 2: реализованы эталоны пересечений (point/overlap/none, вырожденные и почти параллельные случаи), инварианты порядка/поворота, проекции, матрицы viewport, устойчивость площади при origin 1e9, все провайдеры snap, точный ввод длины, driving/reference dimensions, явные junctions, атомарные отказы при конфликтах и возможность редактировать при несвязанных прежних ошибках. Frozen fixtures проверяют отсутствие мутаций. Отверстия/топология комнат и общие нелинейные constraints ещё не реализованы; тесты появятся с соответствующими фазами.

Фаза 3: 143 unit/storage проверки в 9 файлах и 16 Playwright сценариев (8 desktop, 8 mobile Chromium) проходят. Проверены точный прямоугольник 4,257 × 3 м и четыре явных junctions, размеры, полная Undo/Redo, порог drag, перемещение, параметры, delete/undo, pan/pinch, переключение этажа с flush, offline edit/reload и конфликт двух вкладок с восстановлением на отдельном этаже. SaveQueue тестируется с fake timers, in-flight записью, отказом ACK/backup и retry; storage — настоящей миграцией v1, CAS, межэтажной изоляцией и rollback всех таблиц. Числовая привязка проверяется в рассчитанном конце стены, отдельно от короткого луча направления. Полный отчёт — [Фаза 3](phase-3-report.md).

Фаза 4: 170 unit/storage тестов в 10 файлах и 24 Playwright сценария (12 desktop, 12 mobile Chromium). Новые проверки охватывают формы сечений, полости box, повёрнутые составные части, геометрию/валидацию контуров, следование проёмов за стеной, выход за размеры, перекрытия, все типы перемещений, каскадное delete/undo и неподтверждённые параметры. Storage проверяет реальный upgrade v2 с recovery draft, сохранение всех конструкций, rollback, remap wallId и snapshots v2→v3. Браузер создаёт все формы и типы, изменяет составные части, проверяет реальные пиксели слоя, параметры, историю, offline reload и исправление невозможного проёма. [Отчёт Фазы 4](phase-4-report.md).

Фаза 5: эталоны точного прямоугольника/вогнутой комнаты, вращения, T-разделов, отверстий, разрывов и самопересечений; shared-wall/opening spans, объединённые и обрезанные следы колонн, профили и объёмы, кеш зависимостей, недостоверные количества, статусы/undo/перепривязка. Реальные IndexedDB v3→v4 и snapshot v3→v4, rooms roundtrip и восстановление с новыми UUID. Браузер проверяет помещение/количества/статус/проёмы/удаление/offline и сохранённые итоги объекта на desktop и touch viewport.

Фаза 6: детерминированные issues без мутаций, уровни/пересечения/разрывы/дубли/ссылки, safe/stale proposals, запрет нового пересечения, сохранность привязанных данных, отсутствие рекурсии при self-referencing dimension, завершение комнаты с замечаниями. Браузер: явный отказ без правки, подтверждение с сохранением ручных длин, Undo/Redo/reload, offline, переход к проблеме на другом этаже, фильтры, свойства проёма и конфликт вкладок.

Фаза 7: **241 unit/storage/SQL тест** в 15 файлах, **40 обычных browser сценариев** и **10 cloud browser сценариев** (по 5 desktop/mobile). TypeScript, ESLint, production/PWA build проходят. В обычном запуске 10 cloud сценариев явно skipped; они проходят отдельным запуском настроенной сборки с перехватом Auth/RPC. CI содержит оба запуска. SQL миграции реально исполняются в PGlite с моделями auth/storage и ролями: проверяются CAS, SHA-256 idempotency, другой payload с прежним UUID, атомарный отказ, owner RLS и приватные оригиналы. IndexedDB: migration v4→v5, quota rollback, очередь после reopen, in-flight+new edits, duplicate ACK, retry, account scope, stop worker, конфликт и полное переназначение ссылок локальной копии. Browser: SDK вход/регистрация/reset, enrollment, ACK с сохранением локальных данных, сеть/reload/retry, второй браузер, явное принятие конфликта с копией и выход/другой аккаунт. Это не проверка внешнего Supabase: live smoke описан в [инструкции подключения](supabase-setup.md).

Фаза 8: 255 unit/storage/SQL тестов в 16 файлах; 46 обычных browser сценариев и 12 cloud browser сценариев (desktop/mobile). Обычный e2e запуск явно skipped 12 cloud сценариев, отдельная настроенная сборка исполняет их с Auth/RPC/Storage mocks. CI включает оба запуска. Проверяются snapshot v4→v5 и реальная Dexie v5→v6 migration без изменения frozen commands, точные исходные байты/lastModified/checksum, дедупликация, quota/outbox rollback, новые bindings/owner scope/defect CAS, согласованное переназначение фото, метаданные отчёта и неизвестные размеры, MIME/сигнатура/50 МБ, отказ кеширования повреждённого оригинала и conflict copy с доступным файлом. Browser проверяет реальные красные пиксели отметки, превью 1600→1280 px, hash оригинала, offline reload, корзины фото/дефекта/объекта и отдельные project photos. Cloud сценарий допускает принятый metadata RPC, вызывает отказ Storage, проверяет сохранение outbox, retry без второй revision и точные upload байты, затем новое устройство явно скачивает и кеширует оригинал. PGlite применяет 0004, проверяет v5 metadata/path и RLS второго пользователя. Live Supabase/мобильные камеры/HEIC и нагрузка 2000 фото остаются отдельными Beta проверками.

Фаза 9: 273 теста в 17 файлах; 54 обычных browser сценария + 12 отдельных cloud mocks. Новые 18 unit тестов проверяют производную геометрию, объёмы и raycast отверстия; 8 desktop/mobile случаев — камеру, pinch, PNG, offline lazy chunk, WebGL fallback, повторное переключение и источник в 2D. Программный WebGL включён только для three.spec.ts; реальные GPU и нагрузка остаются фазой 12. [Отчёт](phase-9-report.md).

Фаза 10: 295 тестов в 18 файлах, 62 обычных browser сценария + 12 cloud mocks. Проверены цены/округление/переполнение, scopes/происхождение/дефекты, выбор работ, owner isolation, migration v6→v7 и rollback. 8 новых desktop/mobile случаев проверяют реальные PDF/JPEG downloads, кириллицу/страницы, фото/оригиналы, историю/устаревание, первый экспорт offline и квоту с retry. PDF дополнительно прочитан pdftotext. Настоящие мобильные GPU, HEIC и большие отчёты — Beta. [Отчёт](phase-10-report.md).

Фаза 11: 315 тестов в 19 файлах; 68 обычных browser сценариев + 12 отдельных cloud mocks. Новые unit/storage проверки покрывают полный ZIP roundtrip, точные значения/UUID/ссылки, отдельные цены копии, историю и оригинальные байты, JSON-only import, quota rollback и реальный upgrade v7→v8. ZIP проверяется на traversal/absolute/reserved/NFD paths, case duplicates, CRC/SHA, симлинки, неизвестные версии/файлы и поддельный размер deflate. Шесть desktop/mobile сценариев проверяют реальные downloads, все разделы ZIP, импорт без перезаписи, первый импорт offline после reload, последующее редактирование и отказ неполного экспорта. Export tests используют scoped software WebGL. Не пересобирайте обслуживаемый dist одновременно с browser тестами: это удаляет запрошенные lazy chunks. [Отчёт](phase-11-report.md).

Фаза 12: 323 теста в 22 файлах, 68 обычных browser сценариев (12 cloud skipped), 12 отдельных cloud mocks и 9 Beta browser случаев на laptop/tablet/phone viewport. `npm run test:beta:load` проверяет synthetic 20 floors/5000 walls/200 rooms/1000 defects/2000 unique originals и сохраняет artifacts/beta-node-metrics.json. 40 аналитических поворотов/переносов с вычетом окна соблюдают relative error <0,000001. Broad phase сравнивается с exhaustive oracle; EPS/node fallback и crossing/thick viewport bounds покрыты отдельно. `npm run test:beta` проверяет native import, bounded rendered walls, страницы всех media/issues, offline edit/reload, inert user markup, PDF/ZIP и pointercancel. Проверка дожидается расчёта нестыковок всех этажей. Browser artifacts содержат import/all-floor-issues/automation-pan timings и JS heap sample, не FPS/peak device memory. Beta config использует один worker для воспроизводимости профиля; обычный regression — два.

Дополнительные движки: `BETA_ALL_ENGINES=1 npm run test:beta` после установки Playwright Firefox/WebKit; подготовлен ручной CI workflow. Здесь официальные downloads получили 403 Domain forbidden, поэтому Firefox/WebKit не проверены. Это не skipped Chromium сценарии, а отдельный незапущенный набор. Физические devices/live backend и backup — открытые критерии в [release readiness](release-readiness.md). [Отчёт](phase-12-report.md).

Расширение P1 XLSX: 329 unit/storage/SQL/load тестов в 23 файлах. Новые проверки охватывают структуру OOXML, безопасный literal текст, числа/неизвестные цены/исключения, scope, лимиты, immutable историю в пакете 2 и модель 5000 стен. Обычный regression: 70 passed, 12 cloud skipped. Browser XLSX проверяет первый экспорт без сети и повторное скачивание после reload на desktop/mobile; ZIP проверяет defects.xlsx/estimate.xlsx и версию 2. Независимый openpyxl 3.1.5 прочитал unit-файл и оба browser downloads; это не проверка UI настоящего Excel/LibreOffice. [Отчёт](phase-13-report.md).
