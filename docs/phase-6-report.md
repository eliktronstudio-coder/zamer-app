# Фаза 6: нестыковки и предложения исправлений

Добавлена постоянная панель «Нестыковки» с фильтрами и проверками всех этажей объекта. Каждая запись показывает тип, серьёзность, этаж, помещение, элементы и описание. «Показать» выделяет элемент и центрирует viewport; на другом этаже сначала сохраняется текущая сцена, затем открывается нужный этаж.

Rule engine находит разрывы и свободные концы стен, наложения/дубли и некорректные пересечения, проблемы размеров и связей, невозможные/перекрывающиеся проёмы, наложения конструкций, неполные помещения/расчёты и противоречие явно сопоставленных отметок лестницы/пандуса. Панель также отражает реальные локальные конфликты версий и ошибки сохранения. Ошибки не блокируют обычное редактирование; завершение комнаты может выполняться с замечаниями.

Для небольшого разрыва и безопасного дубля доступны предложения с объяснением и явными «Да»/«Нет». Обнаружение и отказ не меняют проект. Применение сохраняет manual input, проверяет актуальность сцены и не допускает новых пересечений или нарушений связей. Команда сохраняется прежним механизмом, поддерживает undo/redo, автоматически обновляет расчёты и список проблем. Подтверждение не переносится на изменившуюся сцену.

## Файлы

- `src/issues/engine.ts`: контракты расширяемых правил, записи, безопасные предложения и проверки команд.
- `src/editor/IssuesPanel.tsx`: постоянная панель, liveQuery всех этажей, фильтры, подтверждение, переход/фокус.
- `src/editor/{store,Canvas,Editor}.ts/tsx`: пересчёт issues, завершение комнаты, camera focus и подключение панели; `src/app/styles.css`: адаптивное оформление.
- `tests/issues/engine.test.ts`, `tests/e2e/issues.spec.ts`, расширение сценария конфликта вкладок в `tests/e2e/editor.spec.ts`.
- README, карта требований, стратегия проверок, data-and-sync и [ADR 0006](adr/0006-issues-and-repairs.md).

## Проверки

Исполняются `npm run check`, `npm run format:check` и production/PWA браузерные сценарии в desktop Chromium и mobile touch viewport. Эталоны проверяют отсутствие мутаций при анализе, сохранение ручных длин, stale proposals, новые коллизии, дубли со связанными данными, уровни, самоссылку размера, завершение с замечаниями и историю. Браузер проверяет отказ/подтверждение, save+undo+redo+reload, offline, переход на другой этаж с выделением, исправление проёма и отображение конфликта вкладок. Результат: **221 unit/storage тест** в 13 файлах и **40 браузерных сценариев** (20 × desktop/mobile) прошли. TypeScript, ESLint, production/PWA build и Prettier проходят. Проверка canvas подтверждает, что после «Показать» выделенная стена действительно нарисована в центре viewport, а не только выбрана в свойствах.

## Ограничения

Поддержаны реальные локальные данные; серверный sync будет фазой 7. Проверки дефектов и цен появятся вместе с сущностями в фазах 8/10. Автоматических существенных исправлений и молчаливого изменения ручных размеров нет. Предложения намеренно ограничены случаями, где можно проверить сохранность данных; сложные разрывы/наложения исправляются через свойства редактора. Отказ запоминается только в открытой сессии для текущей сцены. Для сравнения лестниц/пандусов нужны совпадающие концы двухточечной линии уровня; многоэтажные/площадные связи ещё не реализованы. Попарные проверки и загрузка всех этажей не заменяют нагрузочную проверку 5000 элементов. Детали — ADR 0006.

Следующая фаза 7: backend, аутентификация, синхронизация и восстановление облачных данных. Фаза 6 останавливается на этой границе.

Визуальная проверка 1366×900 и 390×844: отрисовка выбранных стен и подтверждения корректна, ошибок JavaScript и горизонтального переполнения нет.
