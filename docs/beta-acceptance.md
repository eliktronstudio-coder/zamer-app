# Приёмка Beta на реальном устройстве

Проверяйте отдельный тестовый объект. Первый запуск — по постоянному HTTPS адресу с включённой сетью. Сначала дождитесь открытия приложения и активации PWA. До очистки браузера или смены домена сохраните полный ZIP. Эмуляция Chromium, моки и synthetic нагрузка уже проверены; ниже нужны реальные результаты.

## Паспорт проверки

| Поле                        | Результат |
| --------------------------- | --------- |
| Дата и тестировщик          | Заполнить |
| Адрес и версия deployment   | Заполнить |
| Устройство / RAM            | Заполнить |
| OS / версия                 | Заполнить |
| Браузер / версия            | Заполнить |
| Экран / ориентация / стилус | Заполнить |
| Свободное место             | Заполнить |

Для каждого случая поставить «пройден / ошибка / не проверен». При ошибке записать шаги, ожидание, фактический результат и скриншот без личных данных. Не выдавать «не проверен» за успешный результат.

Минимум устройств: Chrome/Android телефон, Safari/iOS телефон, планшет среднего класса и desktop 1366×768. Edge/Opera проверяются отдельно, не по факту использования Chromium. HEIC/стилус — при наличии подходящих устройств; отсутствующие устройства отмечать явно. Не имитировать заполнение диска удалением пользовательских файлов.

## После подключения Supabase

На staging двумя тестовыми пользователями пройти [live smoke](supabase-setup.md): Email Auth/reset, отправка и подтверждённый ACK, загрузка другим устройством, offline retry с фото, конкурирующие правки с сохранением обеих версий, запрет доступа к чужим объектам и private originals. Отдельно проверить backup restore, rate limits и мониторинг. Эти пункты отложены, пока пользователь не подключил Supabase.

Потеря данных, доступ к чужому объекту, ошибки точности базового замера и повторяющийся отказ экспорта блокируют выпуск. [Матрицу](release-readiness.md) обновлять конкретными результатами, а не наличием инструкции.
