# Данные, offline, sync, импорт

## Модель

Полные TypeScript-контракты сущностей: src/domain/model.ts. Wall хранит start/end, measuredLength, thickness, height, floorId, roomIds, metadata. Opening ссылается на wallId, положение offset в метрах вдоль стены; при изменении стены невозможное положение становится issue, без молчаливого перемещения. Dimensions содержат references на элемент/anchor и режим driving/reference. Room хранит topology/holes и независимые geometricallyClosed/status. Фото: отдельный оригинал Blob локально и Storage в облаке, metadata отдельно. Цена отдельно от вычисляемого объёма.

## project.json v5

Текущий контракт: schemaVersion=5, geometrySchemaVersion=4, exportSchemaVersion=5, project, floors[], walls[], junctions[], dimensions[], elements[], rooms[], defects[], photos[]. Бинарные оригиналы сохраняются отдельно; JSON содержит metadata/checksum/пути. UUID и точные числа сохраняются; проверяются ссылки, этажи и дубликаты. parseSnapshot мигрирует v1 (projects/floors/walls), v2 (дополнительно junctions/dimensions) и v3 (дополнительно elements) и v4 (дополнительно rooms) в памяти с пустыми массивами новых сущностей. Неизвестная версия отклоняется без записи. v0 не существовала. Фаза 11 оборачивает snapshot v5 в переносимый package v1; облачный формат не изменён.

Import сначала валидирует и мигрирует в памяти, затем создаёт копию с новой identity и переназначенными UUID в единой транзакции, сохраняя оригинал отдельно; пользователь выбирает новый объект, чужие ownerId не принимаются. Бэкап всегда содержит исходные ID. Roundtrip исходных ID и чисел уже тестируется.

## IndexedDB

Dexie v8: projectWorkPrices (цены импортированной копии), workPrices, estimateSettings, documents (локальные таблицы фазы 10), projects, floors, walls, junctions, dimensions, elements, rooms, sceneRevisions, recoveryDrafts, cloudStates, outbox, cloudConflicts, defects, photos, photoFiles, photoTransfers. Upgrade v5→v6 создаёт media-таблицы и оставляет неизменяемые команды outbox прежними. Upgrade v4→v5 создаёт sync-таблицы без присвоения гостевых объектов аккаунту; project.json теперь v5. Upgrade v3 создаёт rooms и дополняет recovery drafts пустым rooms, сохраняя всё прежнее. Upgrade v2 сохраняет сцены и revision, расширяет recovery drafts пустыми elements. Upgrade v1 сохраняет прежние данные и назначает revision=0. Создание project+floor атомарно; rename/status/addFloor записываются до показа успеха. Сцена редактора сохраняется целиком одной транзакцией через последовательную очередь с debounce 250 ms. До ACK изменения остаются pending; переход по ссылке ждёт flush. CAS по версии этажа предотвращает перезапись из другой вкладки. При сбое подтверждённая резервная копия сохраняется отдельно; восстановление создаёт новый этаж с новыми UUID и переназначенными ссылками, сохраняя основную версию. Подробности и пределы гарантий — [ADR 0003](adr/0003-2d-editor.md).

PWA precache сохраняет shell production build. При первом визите сеть необходима. После загрузки/service-worker activation shell и данные доступны offline. Service worker не перехватывает будущие Auth/API запросы. Обновление shell требует controlled reload после сохранения редактора, поэтому auto-update не включён. Гость явно видит отсутствие облачной копии; private mode/очистка браузера могут удалить локальные данные. Зарегистрированный пользователь может запросить persistent storage в панели аккаунта; браузер вправе отказать.

Корзина сейчас сохраняет данные до восстановления без фоновой очистки; политика 30 дней ещё не реализована. Постоянное удаление потребует проверяемой каскадной очистки таблиц/файлов. Архив/корзина не удаляют этажи.

## Cloud (фаза 7: подготовлено подключение)

Supabase Auth/PostgreSQL/Storage реализованы за адаптером. Внешний проект отложен пользователем; [инструкция подключения](supabase-setup.md), [ADR 0007](adr/0007-cloud-sync.md). Guest ownerId=null остаётся локальным до явного сохранения в облаке. Вход не мешает созданию новых гостевых проектов.

Локальная транзакция меняет данные, revision и durable outbox. Worker фиксирует согласованный snapshot и idempotency UUID; payload при retry не меняется. PostgreSQL CAS сверяет base revision и owner. ACK удаляет только принятую команду, сохраняя локальные данные и новые изменения. Retry с backoff 2–300 секунд, online/таймер/явная кнопка. updatedAt не выбирает победителя. Архив/корзина синхронизируются как статусы, без физического удаления.

cloud_projects/cloud_floors/cloud_entities содержат метаданные/этажи/отдельные типизированные сущности; cloud_versions — неизменяемые backup snapshots, cloud_commands — idempotency responses. Чтение ограничено RLS, запись разрешена через RPC. Приватный bucket подготовлен, загрузка оригиналов появится в фазе 8.

Устаревшая отправка или загрузка новой версии существующего объекта создаёт конфликт. Обе версии остаются раздельно. Явное принятие облачной обязательно сохраняет локальную копию с новыми ID/ссылками; активные recovery drafts сначала восстанавливаются. Отдельный гостевой дубликат можно открыть, оставив исходный конфликт нерешённым. Локальный владелец браузера физически может читать IndexedDB; account scope не является шифрованием. Серверные версии не заменяют независимый инфраструктурный backup.

## Расширения

Интерфейсы MeasurementDevice, AIProvider, DocumentRenderer, SyncTransport, MonitoringSink подключаются отдельно в своих фазах. Ни UI, ни geometry core не зависят от конкретного SDK. Telemetry не отправляет фотографии и содержимое проекта по умолчанию.

## Геометрическое ядро Фазы 2

Junction содержит только явные связи концов стен, без копии координат. Фаза 3 подключила GeometryScene к редактору, Dexie v3 и snapshot v3. Геометрические алгоритмы по-прежнему независимы от React/Konva. Подробнее — [ADR 0002](adr/0002-geometry-core.md) и [ADR 0003](adr/0003-2d-editor.md).

## Строительные элементы Фазы 4

Сцена сохраняет ConstructionElement[] вместе со стенами/связями/размерами. Проёмы хранят wallId и offset; мировое положение вычисляется из текущей стены. При выходе за длину/высоту размеры не меняются и не теряются, отображается предупреждение. Recovery новой копии переназначает ссылки проёмов на скопированные стены. [ADR 0004](adr/0004-construction-elements.md) описывает профили, составные сечения, линии/области уровня и границы гарантий.

## Помещения Фазы 5

Room сохраняет UUID, имя пользователя, floorId, sourceKey, wallIds, контур/отверстия и доли рёбер стен, height|null, geometricallyClosed и независимый status. Замкнутый контур проверяется против стен при чтении/записи. Незамкнутый хранит последнюю границу для ремонта; её площадь не используется. Сцена, rooms и memberships сохраняются атомарно с CAS; recovery переназначает все ссылки. Производные количества вычисляются из сцены без отдельного сохранения. [ADR 0005](adr/0005-rooms-and-quantities.md).

## Нестыковки Фазы 6

Нестыковки и предложения не сохраняются как самостоятельные сущности: rule engine выводит их из сцен после открытия/редактирования/undo. Текущий этаж использует живую сцену, остальные читаются консистентной транзакцией liveQuery. Перенос camera/selection не является командой модели. Подтверждённое исправление — одна обычная команда сцены с прежними CAS/очередью/recovery. Отказ действует только в открытом редакторе для этого fingerprint; нет долговечного автоматического согласия. Контракт IndexedDB/snapshot остаётся v4. [ADR 0006](adr/0006-issues-and-repairs.md).

## Дефекты и фото (фаза 8)

Metadata и оригинал/превью хранятся раздельно. Создание файла атомарно с metadata/revision/outbox; SHA-256 и декодирование выполняются до транзакции. Photo tombstone сохраняет оригинал; archive/trash проекта сохраняют все связи. Defect CAS и новые bindings проверяются; исторические связи после удаления геометрии не теряют данные. Cloud metadata хранится в cloud_defects/cloud_photos, оригиналы — private Storage. Local ACK отправки ждёт проверки файлов, другой клиент может временно получить metadata до окончания upload. Скачивание отдельного оригинала проверяет checksum. Conflict copy требует оригиналы локально, затем переназначает IDs и сохраняет доступ к общим immutable bytes. Подробности и ограничения — [ADR 0008](adr/0008-defects-and-photos.md).

## Производный 3D вид

Фаза 9 строит модель текущего этажа из живой принятой GeometryScene. Mesh содержит UUID источника; отдельная копия геометрии в IndexedDB не сохраняется. Переключение вида не меняет данные и не размонтирует очередь сохранения. Неподтверждённый черновик инструмента не включается в 3D. Схемы и snapshots не менялись. PNG скачивается локально; запись Document и полный экспорт появятся в следующих фазах. [ADR](adr/0009-derived-3d.md).

## Цены и документы фазы 10

Dexie v7 добавляет локальные workPrices, estimateSettings и documents. Цена — целые копейки, ключ включает аккаунт/название/единицу; исключённые строки сохраняются по объекту и аккаунту. Источник документа читается атомарно после flush и хранится вместе с готовыми Blob, ценами, областью, составом и fingerprint. Неизвестные суммы остаются неизвестными. Snapshot v5/RPC v5/outbox не изменялись: эти три таблицы пока не синхронизируются. История гостя доступна после enrollment владельцу объекта. Фаза 11 включает их в переносимый ZIP. [ADR](adr/0010-estimates-and-documents.md).

## Переносимый пакет фазы 11

`format=zamer-project`, запись `packageVersion=2`, чтение версий 1 и 2: snapshot v5, используемые цены, исключённые строки, оригиналы, immutable история и SHA-256/размер/MIME каждого файла. Формат версии пакета независим от Dexie v8 и cloud RPC v5. В ZIP остаются исходные ID, при импорте рабочая модель получает новые UUID и ссылки. Источники/строки исторических документов сохраняют прежние ID для воспроизводимости; готовые файлы не регенерируются.

Проверка ZIP/JSON выполняется Worker до записи; затем единая транзакция сохраняет новую модель, оригиналы, историю, цены и исключения. Ошибка квоты откатывает всё. Импорт создаёт гостевой объект, не переносит owner/auth/outbox/ACK и не включает автоматическое облачное сохранение. Цены копии хранятся отдельно по объекту/текущему аккаунту и не перезаписывают общий справочник; изменение цены пользователем снимает соответствующее переопределение. JSON без ZIP явно переносит только модель/цены/состав без оригиналов и истории. [ADR 0011](adr/0011-portable-project.md).

## QA/Beta фазы 12

Схемы Dexie v8/package v1/cloud snapshot v5 и SQL не изменились. Проверено восстановление синтетического ZIP с 5000 стенами/200 комнатами/1000 дефектами/2000 unique originals в fake IndexedDB с проверкой всех байтов после reopen; native browser проверяет геометрию, 51 photo bindings, пагинацию и offline edit/reload. Culling и страницы списков влияют только на отображение: полная модель/файлы участвуют в сохранении и export. Infrastructure backup/live Storage/физические устройства всё ещё требуют отдельного подтверждения. [Матрица выпуска](release-readiness.md).

XLSX добавлен в допустимые форматы истории и MIME файлов пакета 2. Версия 1 с XLSX отклоняется; старые PDF/JPEG пакеты версии 1 импортируются. Dexie v8, snapshot/RPC v5 и geometry v4 остаются прежними. История XLSX переносится байт в байт, с исходными UUID и зафиксированными расчётами.
