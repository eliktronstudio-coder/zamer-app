# Фаза 7: аккаунты, backend и синхронизация

Реализованы Supabase Auth UI/адаптер, явное подключение гостевого объекта к аккаунту, durable offline очередь, отдельный cloud ACK, повтор после сбоя, загрузка на новое устройство и конфликт без молчаливой перезаписи. Выход/смена аккаунта сохраняют редактор, останавливают прежний worker и скрывают его owned-объекты. Доступен запрос persistent storage.

Добавлены PostgreSQL CAS/idempotency RPC, RLS владельца и private Storage bucket. Геометрия хранится в отдельных типизированных строках, каждая принятая серверная версия имеет неизменяемый резервный snapshot. При принятии облачной версии локальная копия сохраняется отдельным гостевым объектом с новыми UUID и корректными ссылками. Recovery drafts сначала необходимо восстановить.

Пользователь выбрал «Подготовить подключение; Supabase настрою позже». Поэтому внешний проект, ключи, доставка писем и live инфраструктура не подключены. Это завершённая подготовка фазы 7 в указанном объёме, а не подтверждение работы внешнего облака.

## Проверки

**241 unit/storage/SQL тест** в 15 файлах, **40 обычных browser сценариев** и **10 cloud browser сценариев** прошли. TypeScript, ESLint и production/PWA build проходят. В обычном browser запуске cloud-набор отмечен как 10 skipped и проверен отдельно настроенной сборкой с имитацией Auth/RPC endpoints. PGlite реально исполнил все три миграции. Desktop/mobile формы визуально проверены: нет ошибок JavaScript или горизонтального переполнения. Скриншоты: `/tmp/zamer-phase7/desktop.png`, `/tmp/zamer-phase7/mobile.png`. См. [стратегию проверок](testing.md).

## Документы и ограничения

[ADR 0007](adr/0007-cloud-sync.md) описывает протокол, хранение и границы гарантий. [Инструкция Supabase](supabase-setup.md) содержит миграции, публичные переменные и обязательные live smoke проверки после подключения. SQL validation пока не полностью дублирует геометрические/рекурсивные контракты клиента; полноценный публичный запуск требует дополнительного backend hardening, квот, retention и мониторинга. Фото-UI/upload/checksum — фаза 8. Политики bucket подготовлены заранее. IndexedDB v5 и project.json v4 — разные версии, миграция не присваивает гостевые данные аккаунту.

Инструкции `start_skill` облачной среды обновлены и сохранены как черновик; установка, сеть и остальные настройки сохранены без изменений. Публикация выполняется пользователем в настройках среды.
